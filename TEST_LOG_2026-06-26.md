## Firmware Changes

- GEO calibration order is `PGA -> BP -> ADDER -> LP`.
- GEO differential target is `0 counts` for all stages.
- All GEO stage adelantos are near `1.5 V` (`1504 mV`, DAC code `94`) at boot
  and at the start of calibration.
- Gains used by the PI:
  - `GEO_PGA`: dynamic signed gain `1 - GainDirecta`.
  - `GEO_BP`: `+1`.
  - `GEO_ADDER`: `+3`.
  - `GEO_LP`: `+6`.
- `FIR_calibration` is loaded into the hardware `Filter` for calibration.
  `FIR_adquisition` is restored when calibration completes.
- The PI reads the hardware Filter output through `DMA_Filter_RAM`; no software
  averaging/refine pass is used.
- Added `CAL_PI_FIR_SETTLE_SAMPLES = 512` so the FIR can settle after AMux
  switching and filter-history reset before the PI starts moving the DAC.
- Increased `CAL_PI_TIMEOUT_SAMPLES` to `30000` per stage, prioritizing a
  working calibration over speed.
- Removed early abort at DAC rails. A stage now gets the full timeout to let
  the low-cutoff FIR show the effect of the last DAC movement.
- Disabled diagnostic DAC sweeps during normal calibration; they were useful to
  prove authority but too intrusive for the real run.
- If a stage still fails at a rail, the firmware restores that VDAC to the
  stage center/adelanto instead of leaving it saturated.
- `AMux_ADC` selects exactly one signal channel plus the capacitor channel
  (`AMux=4`) during calibration, then disconnects the capacitor and restores
  the capture path at the end.
- Button-triggered calibration remains enabled.
- EEPROM calibration loading on boot is disabled for this bring-up path
  (`PSOC_LOAD_NV_CAL_ON_BOOT=0`) so old saved DAC values do not override the
  adelantos.

Source fixes completed:

- `main.c`: filtered DMA samples now go through
  `psoc_adc_counts_right_aligned(dma_buf_to_i24(g_dma_filt_buf))`, same as
  raw ADC samples. This addresses the web showing around `-20 V` with FIR
  hardware enabled; the ESP/web scale expects right-aligned +/-2.5 V ADC
  counts, not left-aligned Delta-Sigma words.
- `main.c`: when the ESP sends `PSOC_CMD_SELECT_STREAM=1`, firmware reloads
  `g_fir_adquisition_coeffs_q23`, resets Filter history, clears filtered ISR
  sample state, and then selects the Filter route. This prevents the very slow
  calibration FIR from remaining active in acquisition.
- `FIR_adquisition.h`: acquisition FIR coefficients are editable in the header.
  They match the user-provided acquisition array that starts with
  `D4 0A 00 00`.
- `FIR_calibration.h`: calibration FIR coefficients are editable in the header.
  They match the user-provided calibration array and use `0x0A, 0x52` at taps
  13 and 114, matching generated `Filter_Coefficients.c`.
- `FIR_adquisition.c` and `FIR_calibration.c`: now only instantiate the arrays
  from the header macros.
- ESP master web: added `Envolvente` checkbox. It computes a Hilbert envelope
  in browser-side JS (`signal_proc.js`) and applies it only as a plot view.
  It does not alter stored/exported raw or filtered data.
- ESP slave1: `CMD_BLINK_LED` now turns the LED on immediately, uses
  configurable active-low levels, and accepts `node_id=0` broadcast as well as
  the local node id.
